# 科研调研 Skill 武器库（Research Skill Arsenal）设计

> 目标：把“科研调研”能力做成一组**可发布为 DSH 插件的武器（skill）**，供不同问题/科研工作流按需组合。
> 定位：不是一条固定流水线，而是一个**武器库（arsenal）**——每个武器内部规则封闭，武器之间组合开放。
> 状态：设计稿 v0.1（用户讨论收敛中）。

---

## 1. 为什么用“武器库 + 自由度”，而不是固定流程

- 不同研究问题、不同科研工作流，对“调研能力”的需求**不一样**（有的重取证、有的重对抗审稿、有的重门禁纪律）。
- 因此不能把整个流程写死成一条固定流水线；应提供**一组可独立、可组合、可配置的武器**，由使用方按需挑选。
- 这同时回应一个隐患：**agent 在运转时容易“临场补充规则”**——若规则散落在流水线里、由 agent 即兴发挥，就会不可复现、不可审计。

## 2. 三条设计原则

### 原则 A：武器 = 封闭规则（保证下限 / 可复现）
- 每个武器内部的规则**写死、可机器查、不随 agent 临场补充**。
- 落法：skill 用 **prescriptive 约束**（SKILL.md 的“必须/禁止/流程”）+ **机器门**（成败协议、检查清单、脚本）把规则锁死。
- 对应“agent 运转时补充规则”的担忧：**规则属于武器，不属于 agent 的临场发挥**；agent 只能调用武器，不能改写武器内部规则。

### 原则 B：武器库 = 开放组合（提供自由度 / 提高上限）
- 自由度体现在**“选哪些武器、怎么配置、怎么串联”**这一层，由使用方按工作流决定。
- 对抗类武器（红黑队）在组合层把质量天花板抬高；纪律类武器在组合层把下限兜住。

### 原则 C：机制字段无关，领域作可替换配置
- 武器机制层与具体学科解耦（“任意论文/任意手稿/任意 Zotero 集合”都能用）。
- 领域清单（如领域术语表、近5年优先、库内审计规则）**抽成配置项**，换学科只改配置、不改机制。

### 原则 D：武器是飞轮，不是静态成品（自我进化）
- 丰富武器库的核心是**学习**：每个武器都要能“从真实失败里长出规则”并**写回记忆**（对应 flywheel 的“记忆写入”，缺它轮子不转）。
- `red-black-review` 的体现：每轮必写**学习卡**；当红方“挑不出有效错误”或“只会重复旧错”时，触发 **T4 元层**——回到第一性原理（真实性 + 权威性）深挖被遗漏的攻击面，构造新启发并入武器库。
- 层级化（T1 量级快筛 / T2 真实性 / T3 权威性 / T4 元学习）应对不同时期/质量需求；**层级是成本/粒度划分，不是质量等级**（类比物理：数量级估计、抓主要矛盾）。

## 3. 全谱系武器清单（含下限 + 上限）

> 内部规则封闭点 = 该武器“不可被 agent 临场改”的硬约束；自由度/配置点 = 使用方可按工作流调的地方。

### 下限支柱（纪律 / 门禁）——保证“不装读、不杜撰、可追溯、门禁自身也可复现”

| 武器 | 作用 | 内部规则封闭点（可机器查） | 自由度 / 配置点 |
|---|---|---|---|
| `research-gate` | L0 库卫生 + L1 阅读登记 + L2 前向证据链 | 引用-登记对账、证据卡 forward 方向、need_add 报警 | 门禁阈值、领域清单、Zotero 集合 |
| `reverse-reproducibility` | 反向可复现审查：审“门卫/综述自己的工作能否被机器复现” | 证据卡 key 一致性、页码/引文机检、fingerprint | 提取目录、指纹粒度 |
| `zotero-annotations` | 只读批注取证底座（保证“读过的是真批注”） | 只读、无密钥、STATUS/ERROR 协议 | 缓存目录、颜色/页码过滤 |

### 上限支柱（对抗）——红黑队把质量天花板抬高

| 武器 | 作用 | 内部规则封闭点（可机器查） | 自由度 / 配置点 |
|---|---|---|---|
| `red-black-review` | 红方审稿 + 黑方守正回应 + 复审对账，一个完整对抗闭环 | 红方清单（孤例/相关性≠支持/对齐/用词）、黑方回应模板、复审逐条核验 | 攻击面开关、审稿范围（章/段）、领域清单 |
| `review-quality-analyzer` | 综述质量迭代（子代理 A 深度分析 + B 对照反思改进） | 认知顺序“先如何实现、再能做什么”、禁子弹、就地证据 | 提示词版本、对照的“真实综述块” |

### 交付支柱（写作 / 排版）——保证最终交付物可移植、可编译、引用可对账

| 武器 | 作用 | 内部规则封闭点（可机器查） | 自由度 / 配置点 |
|---|---|---|---|
| `latex-research-writing` | 最终成果写成极简 LaTeX 项目：`main.tex` + `chapters/` 按章拆分 + `refs.bib` 集中管理 BibTeX | `main.tex` 唯一入口、`\include` 文件存在、cite key ↔ BibTeX key 对账、无 Markdown 泄漏、至少 2 个章节文件 | 章节清单、标题/作者、BibTeX 风格（默认 `plainnat`）、项目目录名 |

---

## 4. 自由度层设计（组合 / 配置）

- **选武器**：按工作流挑（如“纯取证”只需 zotero-annotations + research-gate；“投稿前”需全谱系）。
- **配武器**：领域清单、证据层级、门禁阈值、对抗轮数、审稿范围等作为配置项。
- **串武器**：武器间可串联成闭环（如 research-gate → red-black-review → reverse-reproducibility），但串联方式由使用方定。
- **不变量**：武器内部规则不改；agent 只能调用，不能改写。
