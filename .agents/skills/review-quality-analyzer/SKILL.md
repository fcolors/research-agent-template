# 综述质量提示词工程（Review Quality Analyzer）

> 核心理念（用户拆解）：看一篇论文，**先想它如何实现、能做什么，再谈价值**；科研与"直接陈述它是什么"相悖。
> 本 skill 用两个子代理的迭代闭环，把"罗列式"升级为"有论点、有机理、有证据批判"的高质量综述叙述。

## 框架（像构建代码一样的迭代）

```
[真实综述 + 其引用的论文全文]
   │ 子代理 A：按 prompts/analyze.md 读论文全文 → 深度分析（如何实现/能做什么/证据与局限/意义）
   ▼
[A 的输出]
   │ 子代理 B：按 prompts/evaluate.md 对照真实综述块 → 评价差距 + 反思改进提示词 + 给出 analyze v2
   ▼
[改进后的 analyze 提示词 v2]
   └─> 回到 A 重跑（可多轮），直到 A 输出接近真实综述的深度
```

## 提示词文件（本 skill 的 prompts/ 下）
- `prompts/analyze.md` —— 子代理 A：科学分析提示词（先如何实现→能做什么→证据与局限→一句话意义）
- `prompts/evaluate.md` —— 子代理 B：评价与反思提示词（对照真实综述块，改进 analyze）

## 使用步骤
1. 选定一篇**高质量、可获取全文**的综述，取其中**一个块**（讲某篇论文/某话题的段落）。
2. 找到该块对应的**论文全文**（或块内引用的那篇）。
3. 子代理 A：喂 `analyze.md` + 论文全文 + 综述块 → 得 A 的输出。
4. 子代理 B：喂 `evaluate.md` + 综述块 + A 的输出 + 当前 analyze 提示词 → 得差距评价 + analyze v2。
5. 用 v2 重跑 A，对比 A 输出是否更接近综述；可再循环。
6. 收敛后，把"分析一篇论文"的稳定提示词沉淀进 `prompts/analyze.md`（或按话题建变体）。

## 与 peer-reviewer 的区别
- peer-reviewer：审一份手稿（红方，挑错/质量门）。
- review-quality-analyzer：**训练"如何把单篇论文写成高质量综述叙述"的提示词**（正向生成深度，而非评审）。
- 两者可配合：先 analyzer 产出深度，再 peer-reviewer 审深度是否到位。

## 局限
- 依赖子代理 A 能读到论文全文（库内 .zotero-extract/ 或粘贴全文）。
- 综述块选择影响基准；选代表性、机理密集的块更能暴露提示词缺口。
